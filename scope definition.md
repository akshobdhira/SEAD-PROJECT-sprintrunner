## 7. Scope Definition – In-Scope

The following features and functionalities are considered **in-scope** for the Sprint Retrospective Analyzer project. These features define the boundaries of what the system will support in the current development phase.

### In-Scope Features

- User authentication and role-based access (Scrum Master, Developer, QA, Product Owner)
- Creation and management of sprint records
- Structured collection of sprint retrospective feedback
- Categorization of feedback into:
  - What Went Well
  - What Didn’t Go Well
  - Action Items
- Storage of retrospective data in a centralized database
- Analysis of retrospective feedback across multiple sprints
- Identification of recurring themes and issues using text analysis techniques
- Tracking of action items across sprints
- Visualization of trends and insights using dashboards and charts
- Viewing historical sprint retrospective data
- Basic reporting for process improvement insights
- Support for academic and training-based Agile teams

These in-scope features ensure that the system effectively supports structured retrospective analysis and enables data-driven continuous improvement within Agile teams.
