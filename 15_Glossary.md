# Glossary
## Sprint Retrospective Analyzer

**Document Version:** 1.0  
**Date:** January 27, 2026  
**Project:** Sprint Retrospective Analyzer

---

## A

**Action Item**  
A specific, measurable task identified during a retrospective to address an issue or implement an improvement. Action items have an owner, due date, and status.

**Acceptance Criteria**  
Conditions that must be met for a requirement or user story to be considered complete and acceptable to stakeholders.

**Agile**  
An iterative approach to software development and project management that emphasizes flexibility, collaboration, and customer feedback.

**Agile Ceremony**  
Structured meeting or event in Agile methodology, such as sprint planning, daily standup, sprint review, or sprint retrospective.

**API (Application Programming Interface)**  
A set of protocols and tools for building software applications, specifying how software components should interact.

**Authentication**  
The process of verifying the identity of a user, typically through username/password or other credentials.

**Authorization**  
The process of determining what an authenticated user is allowed to do within the system (permissions).

**Availability**  
The percentage of time a system is operational and accessible to users, typically measured as uptime.

---

## B

**Backup**  
A copy of data stored separately from the primary system to enable recovery in case of data loss or system failure.

**Baseline**  
A reference point or snapshot of a project deliverable (e.g., requirements, design) used for comparison and change management.

**bcrypt**  
A password hashing algorithm that incorporates a salt and is computationally expensive to resist brute-force attacks.

---

## C

**CASE Tool (Computer-Aided Software Engineering Tool)**  
Software that supports software development activities such as modeling, design, and documentation (e.g., StarUML, Visual Paradigm).

**CCPA (California Consumer Privacy Act)**  
California privacy law granting consumers rights over their personal data, including right to know, delete, and opt-out.

**Circuit Breaker**  
A design pattern that prevents repeated calls to a failing service, allowing it time to recover.

**Class Diagram**  
A UML diagram showing the static structure of a system by displaying classes, attributes, methods, and relationships.

**Continuous Improvement**  
The ongoing effort to improve products, services, or processes through incremental and breakthrough improvements.

**CSV (Comma-Separated Values)**  
A simple file format for tabular data where values are separated by commas.

---

## D

**Dashboard**  
A visual interface displaying key metrics, charts, and data summaries to provide at-a-glance insights.

**Data Retention Policy**  
Rules specifying how long data should be stored before deletion or archiving.

**Deployment Diagram**  
A UML diagram showing the physical deployment of software components on hardware nodes.

**DevOps**  
A set of practices combining software development (Dev) and IT operations (Ops) to shorten development cycles and improve deployment frequency.

---

## E

**Effectiveness Score**  
A metric measuring whether a completed action item successfully resolved the issue it addressed (based on issue recurrence).

**Encryption**  
The process of encoding data to prevent unauthorized access, using algorithms and keys.

**End User**  
The person who ultimately uses the software system (e.g., team member, Scrum Master, manager).

**Epic**  
A large user story or requirement that is broken down into smaller, manageable stories for implementation.

---

## F

**Failover**  
The automatic switching to a backup system or component when the primary one fails.

**Fault Tolerance**  
The ability of a system to continue operating despite component failures.

**Feedback**  
Input provided by team members during a retrospective about what went well, what didn't, and what to improve.

**Functional Requirement**  
A specification of what the system should do, describing specific behaviors or functions.

---

## G

**GDPR (General Data Protection Regulation)**  
European Union regulation on data protection and privacy, granting individuals rights over their personal data.

**Graceful Degradation**  
The ability of a system to maintain limited functionality when part of it fails, rather than failing completely.

---

## H

**High Availability**  
A system design approach and associated service implementation that ensures a certain level of operational performance, usually uptime.

**Horizontal Scaling**  
Adding more machines or instances to distribute the load (scale out), as opposed to increasing the capacity of a single machine (scale up).

---

## I

**Implementation Plan**  
A detailed document outlining how requirements will be implemented, including technical approach, timelines, and resources.

**Include Relationship**  
A UML relationship where one use case always includes the functionality of another use case.

**Iteration**  
A single development cycle in Agile, typically equivalent to a sprint, where a working increment is produced.

---

## K

**Kanban**  
An Agile methodology that visualizes work on a board and limits work in progress to improve flow and efficiency.

**Keyword Extraction**  
The process of automatically identifying important words or phrases from text, used for pattern recognition.

**KPI (Key Performance Indicator)**  
A measurable value that demonstrates how effectively key objectives are being achieved.

---

## L

**Load Balancer**  
A device or software that distributes network traffic across multiple servers to ensure no single server is overwhelmed.

**Load Testing**  
Testing methodology to determine system behavior under expected and peak load conditions.

**Longitudinal Analysis**  
Analysis of data collected over time to identify trends and patterns.

---

## M

**Manager**  
A user role with permissions to view cross-team analytics, generate reports, and oversee multiple teams.

**MVP (Minimum Viable Product)**  
The simplest version of a product that can be released to satisfy early customers and provide feedback for future development.

---

## N

**NFR (Non-Functional Requirement)**  
A specification of how the system should behave, describing quality attributes like performance, security, and usability.

**NLP (Natural Language Processing)**  
A branch of AI that helps computers understand, interpret, and generate human language.

**Notification**  
An alert sent to users (via email or in-app) to inform them of events like new retrospectives or action item assignments.

---

## P

**Pattern**  
A recurring theme, issue, or feedback point that appears across multiple retrospectives.

**Pattern Recognition**  
The automated process of identifying recurring themes and issues from retrospective feedback.

**Persona**  
A fictional character representing a user type, used to understand user needs and behaviors.

**PII (Personally Identifiable Information)**  
Any data that could potentially identify a specific individual (e.g., name, email, ID number).

**Priority**  
The importance level of a requirement or task, typically categorized as High (P1), Medium (P2), or Low (P3).

**Product Owner**  
The person responsible for defining and prioritizing the product backlog and ensuring the team delivers value.

---

## R

**RBAC (Role-Based Access Control)**  
A security approach that restricts system access based on user roles and associated permissions.

**Recurring Issue**  
A problem or concern mentioned in 3 or more consecutive sprints, indicating a systemic issue.

**REST (Representational State Transfer)**  
An architectural style for designing networked applications using HTTP requests (GET, POST, PUT, DELETE).

**Retrospective**  
An Agile ceremony held at the end of a sprint where the team reflects on what went well, what didn't, and what to improve.

**RTO (Recovery Time Objective)**  
The maximum acceptable time to restore a system after a failure.

**RPO (Recovery Point Objective)**  
The maximum acceptable amount of data loss measured in time (e.g., 24 hours).

---

## S

**Scalability**  
The ability of a system to handle increased load by adding resources (horizontal or vertical scaling).

**Scrum**  
An Agile framework for managing work with an emphasis on software development, using iterative sprints.

**Scrum Master**  
A facilitator role in Scrum responsible for ensuring the team follows Agile practices and removing obstacles.

**Sentiment Analysis**  
The use of NLP to determine the emotional tone (positive, negative, neutral) of text feedback.

**Sequence Diagram**  
A UML diagram showing how objects interact in a particular sequence to accomplish a task.

**Session**  
A period of user interaction with the system, typically tracked by a session token after authentication.

**Sprint**  
A time-boxed iteration in Agile (typically 1-4 weeks) during which a team completes a set of work.

**Stakeholder**  
Any person or organization with an interest in or affected by the project (e.g., users, sponsors, team members).

**SRS (Software Requirements Specification)**  
A comprehensive document describing the functional and non-functional requirements of a software system.

---

## T

**Team Health**  
An aggregate measure of team satisfaction, morale, and productivity based on retrospective data and sentiment.

**Team Member**  
A user role representing a developer, tester, or designer who participates in retrospectives.

**Technical Debt**  
The implied cost of additional work caused by choosing an easy solution now instead of a better approach that would take longer.

**Third-Party Integration**  
Connecting the Sprint Retrospective Analyzer with external tools like Jira, Slack, or calendar systems.

**Throughput**  
The number of transactions or operations a system can process in a given time period.

**TLS (Transport Layer Security)**  
A cryptographic protocol for secure communication over a network, successor to SSL.

**Traceability**  
The ability to trace requirements through design, implementation, and testing to ensure all requirements are addressed.

**Trend**  
A pattern's behavior over time, such as increasing, decreasing, or remaining stable.

---

## U

**UAT (User Acceptance Testing)**  
Testing performed by end users to validate that the system meets their needs and requirements.

**UI (User Interface)**  
The visual elements through which users interact with the system.

**UML (Unified Modeling Language)**  
A standardized modeling language for visualizing software system design through diagrams.

**Uptime**  
The percentage of time a system is operational and available, typically expressed as a percentage (e.g., 99.5%).

**Use Case**  
A description of how a user interacts with the system to achieve a specific goal.

**Use Case Diagram**  
A UML diagram showing the relationships between actors and use cases in a system.

**User Story**  
A short, simple description of a feature from the perspective of the end user: "As a [role], I want [goal] so that [benefit]."

**UX (User Experience)**  
The overall experience a user has when interacting with a system, including usability, accessibility, and satisfaction.

---

## V

**Validation**  
The process of ensuring a system meets user needs and requirements (building the right system).

**Verification**  
The process of ensuring a system is built according to specifications (building the system right).

**Version Control**  
A system for tracking changes to code and documents over time (e.g., Git).

---

## W

**WCAG (Web Content Accessibility Guidelines)**  
International standards for making web content accessible to people with disabilities.

**Workflow**  
A sequence of steps or activities required to complete a process or task.
